## What this chapter is about

Algebra isn't only for solving equations in a test. It is the secret behind many **tricks and puzzles**: guessing a friend's birthday from one number, filling number pyramids, finding hidden values in grids, and spotting why a "magic" number always appears. In this chapter you will:

- explain "Think of a number" and birthday tricks, and invent your own;
- fill **number pyramids** quickly, and find the top without building the whole pyramid;
- crack calendar and shape **grids**;
- find the **largest product** you can make from three digits, and prove it;
- explain **divisibility tricks** (why 74 − 47 is a multiple of 9), and solve word puzzles.

> [!NOTE]
> **The one idea.** Call the unknown number a **letter** (x, M, a, …). Follow the trick's steps with the letter. If the letter **cancels out**, the answer is the same for everyone. If it doesn't, you can **work backwards** to find it.

## 13.1 "Think of a number" tricks

1. Think of a number. 2. Double it. 3. Add 4. 4. Divide by 2. 5. Subtract the number you first thought of. **The answer is always 2.**

**Why:** follow the steps with x: x → 2x → 2x + 4 → x + 2 → (x + 2) − x = **2**. The x disappears, so the starting number doesn't matter.

> [!IMPORTANT]
> A "think of a number" trick works when every step can be written with the letter, and the **letter cancels** at the end. The constant left over is the "magic" answer.

**Example 1: guessing a date.** Mukta thinks of a date. Shubham tells her: multiply the month by 5, add 6, multiply by 4, add 9, multiply by 5, add the day. She says **291**. Shubham replies, "26 January!"

With month M and day D:
1. ×5: 5M; +6: 5M + 6; ×4: 20M + 24; +9: 20M + 33; ×5: **100M + 165**; + day: **100M + 165 + D**.
2. 291 − 165 = 126 = 100M + D.
3. D is at most 31, so it fills the **last two digits**; the rest is M. So M = 1, D = 26: **26 January**.

With 1390: 1390 − 165 = 1225, so M = 12, D = 25: **25 December**.

**Try this.** Do the date trick on your family with their birthdays. Each time, subtract 165 and read off month and day. Does it ever fail?

### Check yourself

**1.** How would you change the first trick so the answer is always 3? Always 5?

> [!ANSWER]
> In the trick, "add 4, then divide by 2" left **4 ÷ 2 = 2**. So add **twice** the answer you want:
> - **Answer 3:** double, **add 6**, halve, subtract the start: x → 2x + 6 → x + 3 → 3.
> - **Answer 5:** double, **add 10**, halve, subtract the start: x + 5 − x = 5.
>
> Or keep "add 4" and add 1 (or 3) at the end.

**2.** Make up a longer trick that always gives the same answer.

> [!ANSWER]
> For instance: think of x; add 3 (x + 3); multiply by 4 (4x + 12); subtract 8 (4x + 4); divide by 4 (x + 1); add 9 (x + 10); subtract the starting number: **10**, always.
>
> **How to design one:** only use steps you can write with x, and make sure that by the end the x's add up to **zero**. Dividing must be by a number that divides every term (here 4 divides 4x and 4).

**3.** Using the date trick, which dates give the answers (i) 1269 (ii) 394 (iii) 296?

> [!ANSWER]
> Subtract 165; the last two digits are the day and the rest is the month:
> 1. **(i)** 1269 − 165 = 1104 → month 11, day 04: **4 November**.
> 2. **(ii)** 394 − 165 = 229 → month 2, day 29: **29 February** (a leap-year birthday!).
> 3. **(iii)** 296 − 165 = 131 → month 1, day 31: **31 January**.

**4.** Can you change the steps of the date trick and still find the date? What do you subtract then?

> [!ANSWER]
> Yes, as long as the month ends up multiplied by **100** (so it sits in front of the day's two digits). For instance: multiply the month by 5, add **7**, multiply by 4, add **3**, multiply by 5, add the day.
> - 5M + 7 → 20M + 28 → 20M + 31 → **100M + 155** → 100M + 155 + D.
> - So subtract **155** instead of 165.
>
> **Rule:** the number to subtract is whatever constant your steps produce. Work it out by putting M = 0, D = 0 through the steps.

**5.** Devise your own "think of a number" trick.

> [!ANSWER]
> One idea that **reveals** the number: think of x; multiply by 3 (3x); add 7 (3x + 7); double (6x + 14); subtract 2 (6x + 12); divide by 6 (x + 2); tell me the answer. I subtract 2 to get x.
>
> One that **predicts** an answer: think of x; add 5; multiply by 2; subtract 4; divide by 2; subtract x: always **3** (x + 5 → 2x + 10 → 2x + 6 → x + 3 → 3).
>
> Test your trick with three numbers, including 0 and a negative number, before showing it to anyone.

## 13.2 Number pyramids

In a **number pyramid**, each box is the **sum of the two boxes directly below it**.

![A pyramid with bottom row 1, 9, 4; middle 10, 13; top 23](assets/img/class8/math/13/pyramid_rule.svg)

**Going down** a pyramid uses subtraction. If the top is 10 with 4 on its left, the box on the right is 10 − 4 = 6; then the box under 4 next to 1 is 4 − 1 = 3, and so on.

**Example 2: a pyramid with a gap in the middle.** Top 60, bottom row 12, ?, 8. Neither middle box can be found by subtracting yet. Use letters:

![Left: pyramid 60 / a, b / 12, c, 8. Right: filled in: 60 / 32, 28 / 12, 20, 8](assets/img/class8/math/13/pyramid_60.svg)

1. a = 12 + c and b = c + 8, and a + b = 60.
2. So (12 + c) + (c + 8) = 60, i.e. 20 + 2c = 60.
3. 2c = 40, **c = 20**; then a = 32, b = 28.

### The top from the bottom row

Write the bottom row as letters and add upwards:
- 2 rows: a, b → top **a + b**.
- 3 rows: a, b, c → a + b, b + c → top **a + 2b + c**.

![Letter pyramids: 3 rows give a + 2b + c; 4 rows give a + 3b + 3c + d](assets/img/class8/math/13/pyramid_letters.svg)

> [!IMPORTANT]
> The top of a pyramid is the bottom numbers multiplied by **1, 2, 1** (3 rows), **1, 3, 3, 1** (4 rows), **1, 4, 6, 4, 1** (5 rows), and so on, then added.
> **Why:** each box passes its value up to the two boxes above it, so a bottom number reaches the top along several paths. A middle number has more paths to the top than an end number, so it counts more times.

> [!ANSWER]
> Every box is still a Virahāṅka–Fibonacci number (each row is the sequence moved further along). The pattern of tops is 3 rows → 5th number, 4 rows → 7th, so n rows → the **(2n − 1)th** number. **6.** If the bottom row of an n-row pyramid holds the first n Virahāṅka–Fibonacci numbers, what can you say about the pyramid and its top?

> [!ANSWER]
> 1. **Every box is a Virahāṅka–Fibonacci number.** Two neighbours in the sequence add up to the next number, so each row is a later stretch of the sequence: the row above 1, 2, 3, 5, … starts 3, 5, 8, …; the next starts 8, 13, …
> 2. Each row moves **two places** further along the sequence at its start. The bottom row starts at the 1st number, so row k (from the bottom) starts at the (2k − 1)th.
> 3. The top is row n, so it is the **(2n − 1)th** Virahāṅka–Fibonacci number.

## 13.3 Calendar magic

A friend picks a 2 × 2 square of dates and tells you only the **sum**. You name the four dates.

![August 2025 calendar with 6, 7, 13, 14 highlighted: 6 + 7 + 13 + 14 = 40](assets/img/class8/math/13/calendar_aug.svg)

**Why it works:** if the top-left date is a, the others are a + 1 (next day), a + 7 (a week later) and a + 8. The sum is **4a + 16**.

**Example 3: the sum is 36.** 4a + 16 = 36, so 4a = 20 and **a = 5**. The square is 5, 6 / 12, 13.

**Example 4.** Row 1: square + square + square = 27, so a square is **9**. Row 2: circle + circle + square = 19, so 2 × circle = 10 and a circle is **5**.

**1.** Create your own calendar trick with a grid of a different size or shape.

> [!ANSWER]
> **3 × 3 square:** with centre c, the nine dates are c − 8, c − 7, c − 6, c − 1, c, c + 1, c + 6, c + 7, c + 8. They add to **9c**: the +'s and −'s cancel in pairs. So ask for the sum, **divide by 9** to get the centre date, and fill in the rest. (Sum 117 → centre 13.)

## 13.5 The largest product

Put the digits 2, 3 and 5 into □□ × □ (each once). What is the largest product?

There are 6 ways. Group them by the multiplier: 35 × 2 or 53 × 2; 25 × 3 or 52 × 3; 23 × 5 or 32 × 5. In each pair the bigger two-digit number wins, leaving **53 × 2, 52 × 3, 32 × 5**.
- 52 × 3 beats 53 × 2 (a multiplier of 3 against 2, with almost the same two-digit number).
- 52 × 3 = 50 × 3 + 2 × 3 and 32 × 5 = 30 × 5 + 2 × 5. The first parts are equal (150), and 2 × 5 > 2 × 3.

So **32 × 5 = 160** is the largest.

**Try this.** With the digits 2, 4, 6 and 8, what is the largest product □□ × □□? Try a few and look for a rule. (Hint: the two biggest digits go in the tens places.)

**Proof for any digits p < q < r.** The three candidates are rq × p, rp × q and qp × r.
- rp × q > rq × p, because the multiplier q is bigger than p and the tens digit is the same.
- qp × r = 10qr + pr and rp × q = 10rq + pq. The first terms are equal; pr > pq because r > q.

> [!IMPORTANT]
> **Largest □□ × □ from three different digits:** use the **largest digit as the multiplier**, and put the other two **in decreasing order** for the two-digit number.
> **Why:** the largest digit multiplies both other digits, and the tens parts come out equal whichever way, so the units part decides.

## 13.6 Decoding divisibility tricks

Mukta's trick: pick a two-digit number with different digits, reverse it, subtract the smaller from the larger, divide by 9. **There is never a remainder.** (47 → 74, 74 − 47 = 27, 27 ÷ 9 = 3.)

**Why:** write the number as ab = 10a + b; reversed it is ba = 10b + a. If b > a:

(10b + a) − (10a + b) = 9b − 9a = **9(b − a)**, a multiple of 9.

> [!TIP]
> **Write a number by its digits: ab = 10a + b, abc = 100a + 10b + c.** Most digit tricks fall apart once you do this.

### Check yourself

**1.** What happens in Mukta's trick if a > b?

> [!ANSWER]
> Then ab is the larger number, and the difference is (10a + b) − (10b + a) = 9a − 9b = **9(a − b)**, still a multiple of 9. For instance 83 − 38 = 45 = 9 × 5. So the trick works either way.

## Exercises — try first

### 1. In Mukta's trick, what is the quotient after dividing by 9? How is it related to the number?

> [!ANSWER]
> The difference is 9 × (difference of the digits), so the **quotient is the difference between the two digits**. For 47: 7 − 4 = 3, and 27 ÷ 9 = 3 ✓. For 92: 92 − 29 = 63 = 9 × 7, and 9 − 2 = 7 ✓.

### 2. Instead of subtracting, add the number and its reverse (31 + 13 = 44, 28 + 82 = 110, 12 + 21 = 33). Is the sum always divisible by 11? Prove it.

> [!ANSWER]
> **Yes.** (10a + b) + (10b + a) = 11a + 11b = **11(a + b)**. The quotient is even the **sum of the digits**: 44 = 11 × 4 (3 + 1), 110 = 11 × 10 (2 + 8).

### 3. Take a 3-digit number abc and make bca and cab by moving the digits round. Show that abc + bca + cab is always divisible by 37. Is it also always divisible by 3?

> [!ANSWER]
> 1. abc = 100a + 10b + c, bca = 100b + 10c + a, cab = 100c + 10a + b.
> 2. Each digit appears once in each place, so the sum = 111a + 111b + 111c = **111(a + b + c)**.
> 3. 111 = 3 × 37, so the sum is a multiple of **37** and also of **3**.
>
> For instance 123 + 231 + 312 = 666 = 37 × 18 = 3 × 222.

### 4. Write a 3-digit number twice to make a 6-digit number (abc → abcabc). Divide by 7, then by 11, then by 13. What do you get? Why?

> [!ANSWER]
> You get **abc back**. For instance 472472 ÷ 7 = 67496, ÷ 11 = 6136, ÷ 13 = **472**.
>
> **Why:** abcabc = abc × 1000 + abc = abc × **1001**, and 1001 = 7 × 11 × 13. Dividing by 7, 11 and 13 divides by 1001, leaving abc. (No remainder at any step, because 1001 is a multiple of each.)

### 6. A farm's horses and hens have 55 heads and 150 legs. How many of each? Can you solve it without letters?

> [!ANSWER]
> **With letters:** h horses and 55 − h hens. Legs: 4h + 2(55 − h) = 150, so 2h + 110 = 150 and **h = 20**. So **20 horses and 35 hens**.
>
> **Without letters:** if all 55 were hens, there would be 110 legs. There are 40 more. Each horse adds 2 extra legs, so there are 40 ÷ 2 = **20 horses**, and 35 hens. Check: 80 + 70 = 150 ✓.

### 7. A mother is 5 times her daughter's age. In 6 years she will be 3 times her daughter's age. How old is the daughter now?

> [!ANSWER]
> Daughter d, mother 5d. In 6 years: 5d + 6 = 3(d + 6) = 3d + 18, so 2d = 12 and **d = 6**. The daughter is **6** and the mother 30. Check: in 6 years, 36 = 3 × 12 ✓.

> [!ANSWER]

### 9. A dosa cart costs ₹5000 a day in rent, and each dosa costs ₹10 to make.

**(i)** Selling 100 dosas a day, what price gives a profit of ₹2000?

> [!ANSWER]
> 1. Costs for the day: 5000 + 100 × 10 = ₹6000.
> 2. For ₹2000 profit, sales must be 6000 + 2000 = ₹8000.
> 3. Price = 8000 ÷ 100 = **₹80 per dosa**.

**(ii)** If customers pay only ₹50 a dosa, how many must be sold for a ₹2000 profit?

> [!ANSWER]
> Each dosa earns 50 − 10 = ₹40 towards rent and profit. We need 5000 + 2000 = ₹7000, so **7000 ÷ 40 = 175 dosas**. (Equation: 50n − 10n − 5000 = 2000.)

### 10. Work out 1/3, (1 + 3)/(5 + 7), (1 + 3 + 5)/(7 + 9 + 11). What do you notice? Why?

> [!ANSWER]
> 1/3, 4/12 = **1/3**, 9/27 = **1/3**. **Always 1/3.**
>
> **Why:** the sum of the first n odd numbers is n². The top is the first n odd numbers, n². The bottom is the **next** n odd numbers: (first 2n odd numbers) − (first n) = (2n)² − n² = 3n². So the fraction is n²/3n² = 1/3 every time.

### 11. Karim and the genie. Each time Karim walks round a tree his coins double, and then he pays the genie 8 coins. After three rounds he has exactly 8 coins, which all go to the genie, leaving him nothing.

![7 coins: ×2 = 14, −8 = 6; ×2 = 12, −8 = 4; ×2 = 8, −8 = 0](assets/img/class8/math/13/karim.svg)

**(i)** How many coins did Karim start with?

> [!ANSWER]
> Start with x: after round 1, 2x − 8; round 2, 4x − 24; round 3, 8x − 56. This is 0, so 8x = 56 and **x = 7**.
>
> **Working backwards** is quicker: he ended with 0 after paying 8, so before paying he had 8, and before doubling 4; before paying in round 2 he had 4 + 8 = 12, before doubling 6; before round 1's payment 6 + 8 = 14, so he started with **7**.

**(ii)** What cost per round should Karim accept if he wants his coins to grow?

> [!ANSWER]
> With c coins in his pocket and a fee f, one round leaves 2c − f. This is more than c when **f < c**. Starting with 7, he should accept a fee **below 7 coins**; then every round leaves him with more, so the next round is safe too. (A fee of exactly 7 keeps him at 7 for ever.)

**(iii)** The genie knows how many coins Karim has. How should it set the fee to take everything (in three rounds)?

> [!ANSWER]
> After three rounds Karim has 8x − 7f (as in (i), with f instead of 8). For this to be 0, **f = 8x/7**: the fee must be 8/7 of Karim's starting coins. With 7 coins that is **8**, exactly what the genie asked for. (With 14 coins it would ask 16.)

## In a nutshell

> [!IMPORTANT]
> - **Name the unknown with a letter and follow the steps.** If it cancels, the answer is fixed; if not, work backwards.
> - **Date trick:** the steps give 100M + 165 + D; subtract 165 and read month and day.
> - **Number pyramids:** top = bottom × (1, 2, 1) for 3 rows, (1, 3, 3, 1) for 4 rows. Use letters for gaps.
> - **Calendar squares:** a, a + 1, a + 7, a + 8, total 4a + 16. A 3 × 3 square totals 9 × centre.
> - **Largest □□ × □:** biggest digit as multiplier, the others in decreasing order.
> - **Digit tricks:** ab − ba = 9(a − b); ab + ba = 11(a + b); abc + bca + cab = 111(a + b + c); abcabc = abc × 1001 = abc × 7 × 11 × 13.

> [!WARNING]
> **Top traps:** subtract the trick's constant (165) **before** reading the date • in a pyramid, a middle box counts **more** than an end box • the date's day always takes **two** digits (26 January gives 126, not 1260) • "twice as many" means multiply, so Naina has 2g, not g + 2 • work-backwards puzzles: undo steps in **reverse order** (subtract before halving).
