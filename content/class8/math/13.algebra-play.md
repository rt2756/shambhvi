**Every "magic" number trick is algebra in disguise.** This chapter takes tricks apart and shows exactly why they can't fail.

## Think-of-a-number tricks

```
1. Think of a number.        x
2. Double it.                2x
3. Add four.                 2x + 4
4. Divide by two.            x + 2
5. Subtract your number.     x + 2 − x = 2
```

**The x vanishes** — so the answer is **2** whatever you started with.

> [!IMPORTANT]
> **A trick works exactly when the unknown cancels out.** The steps are designed so the starting number disappears, leaving a constant.
>
> **To make the answer 3 instead**, add **six** at step 3 (`2x + 6 → x + 3 → 3`). For 5, add **ten**. The answer is always **half of what you add**.

### The date trick

```
Think of a date (month M, day D).
Multiply the month by 5:   5M
Add 6:                     5M + 6
Multiply by 4:             20M + 24
Add 9:                     20M + 33
Multiply by 5:             100M + 165
Add the day:               100M + 165 + D
```

**To decode: subtract 165 from the answer, and you're left with `100M + D`.**

Since a day is at most 31, **D occupies the last two digits and M is everything before**.

- Answer **291** → `291 − 165 = 126` → `M = 1, D = 26` → **26 January**
- Answer **1390** → `1390 − 165 = 1225` → `M = 12, D = 25` → **25 December**
- Answer **1269** → `1269 − 165 = 1104` → `M = 11, D = 4` → **4 November**
- Answer **394** → `394 − 165 = 229` → `M = 2, D = 29` → **29 February**
- Answer **296** → `296 − 165 = 131` → `M = 1, D = 31` → **31 January**

> [!TIP]
> **Why the messy-looking steps?** The chain `×5, ×4, ×5` multiplies M by **100**, which parks it clear of the two digits that D needs. The `+6, +9` are camouflage — they just pile up into the constant **165** you subtract at the end.
>
> **Design your own:** any sequence of multiplications giving ×100 works; whatever constant it produces becomes your subtraction number.

## Number pyramids

**Each number is the sum of the two directly below it.**

```
        23
     10    13
   1     9     4
```

### Filling from the top down

```
        10                    10                    10
     4     ?      →        4     6      →        4     6
   1    ?    ?           1    3    ?           1    3    3
```

**Why:** if `4 + ? = 10` then `? = 6`. If `1 + ? = 4` then `? = 3`. Each blank is a **subtraction**.

### When you can't start at a corner

```
        60
     a     b
  12    c     8
```

`a = 12 + c` and `b = c + 8` and `a + b = 60`, so

```
(12 + c) + (c + 8) = 60
20 + 2c = 60
c = 20
```

giving `a = 32`, `b = 28`.

> [!TIP]
> **When arrows don't chain, name the unknown and write equations.** Two sums meeting at the top always give you one equation in one unknown.

### The general formula

```
 3 rows:            a + 2b + c
                 a+b       b+c
              a        b        c

 4 rows:      a + 3b + 3c + d
```

> [!IMPORTANT]
> **The coefficients are the binomial numbers 1, 2, 1 and 1, 3, 3, 1** — Pascal's triangle!
>
> **Why:** the top gets one contribution for each **path down** to a bottom cell. Middle cells have more paths than corner cells, so their values get counted more times.

**Shortcut examples (no pyramid needed):**
- bottom `4, 13, 8` → `4 + 2(13) + 8 =` **38**
- bottom `7, 11, 3` → `7 + 22 + 3 =` **32**
- bottom `10, 14, 25` → `10 + 28 + 25 =` **63**
- bottom `8, 19, 21, 13` → `8 + 3(19) + 3(21) + 13 =` **141**
- bottom `7, 18, 19, 6` → `7 + 54 + 57 + 6 =` **124**
- bottom `9, 7, 5, 11` → `9 + 21 + 15 + 11 =` **56**

### Virahāṅka–Fibonacci pyramids

The sequence 1, 2, 3, 5, 8, 13, … has each term the sum of the two before it — **exactly the pyramid rule**.

Bottom row `1, 2, 3`:

```
        8
     3     5
   1    2    3
```

**Every number in the pyramid is a Virahāṅka–Fibonacci number**, and the top is the **next one along**.

**Why:** the rule that builds the pyramid *is* the rule that builds the sequence, so each row is just a shifted copy of the sequence. With n rows and the first n terms on the bottom, the apex is the **(2n − 1)th** term. For 29 rows, the top is the **57th** Virahāṅka–Fibonacci number.

## Fun with grids

### Calendar magic

In a calendar, a `2 × 2` block is

```
   a      a+1
  a+7    a+8
```

(the `+7` because a week is 7 days).

**Sum `= 4a + 16`.** Given the sum, you can recover everything:

sum 36 → `4a = 20` → `a = 5` → the block is **5, 6, 12, 13**.
sum 40 → `4a = 24` → `a = 6` → the block is **6, 7, 13, 14**.

> [!TIP]
> **Design your own.** For a `3 × 3` block with centre c, the nine entries are `c−8, c−7, c−6, c−1, c, c+1, c+6, c+7, c+8` and the **sum is `9c`** — so the sum divided by 9 is the middle date. Neat and instant.

### Shape grids

Each row's last cell is the sum of the shapes to its left.

```
■ + ■ + ■ = 27      →  ■ = 9
▲ + ▲ + ■ = 19      →  2▲ + 9 = 19  →  ▲ = 5
```

**Why start with the first row:** it has only **one kind of shape**, so it solves immediately. Then substitute forward.

> [!TIP]
> **Always attack the row (or column) with the fewest different shapes first.** Each solved shape turns the next row into a simpler equation.

## The largest product

Fill `2, 3, 5` into `□□ × □` to maximise the product.

**All six options:** `23×5, 25×3, 32×5, 35×2, 52×3, 53×2`

**Step 1 — within each multiplier, put the bigger digit in the tens place:**
`53×2 > 35×2` · `52×3 > 25×3` · `32×5 > 23×5`

**Step 2 — compare the three survivors.** `52×3 = 156` beats `53×2 = 106`. Then compare `52×3` with `32×5`:

```
32 × 5 = (3 × 10 × 5) + (2 × 5) = 150 + 10 = 160
52 × 3 = (5 × 10 × 3) + (2 × 3) = 150 +  6 = 156
```

**The first terms are identical** (`10 × 3 × 5` either way), so the winner is decided by the second term — and `2 × 5 > 2 × 3`.

**Answer: `32 × 5 = 160`.**

> [!IMPORTANT]
> **The general rule (with p `<` q `<` r): put the LARGEST digit as the single multiplier, and the other two in decreasing order as the two-digit number.**
>
> **Why:** in `qp × r` versus `rp × q`, the tens contribution is `10qr` both times — identical. The units contribution is `pr` versus `pq`, and since `r > q`, the first wins.

**Worked:** digits 1, 3, 7 → **`31 × 7 = 217`** (check `71 × 3 = 213`, `73 × 1 = 73`).
**Worked:** digits 3, 5, 9 → **`53 × 9 = 477`** (check `93 × 5 = 465`, `95 × 3 = 285`).

## Decoding divisibility tricks

### Reverse and subtract → always divisible by 9

Take `47`, reverse to `74`, subtract: `74 − 47 = 27 = 9 × 3`.

**Why:** the number is `10a + b`, its reverse `10b + a`.

```
(10b + a) − (10a + b) = 9b − 9a = 9(b − a)
```

**Always a multiple of 9** — and the **quotient is `b − a`, the difference of the digits**.

For `74 − 47`: `b − a = 7 − 4 = 3`, and indeed `27 ÷ 9 = 3` ✓

(If `a > b` the difference is negative; take the **absolute** difference and the same rule holds.)

### Reverse and add → always divisible by 11

`31 + 13 = 44` · `28 + 82 = 110` · `12 + 21 = 33`

**Why:**

```
(10a + b) + (10b + a) = 11a + 11b = 11(a + b)
```

**And the quotient is `a + b`, the digit sum.**

### Cycling a 3-digit number → divisible by 37

Take `abc`, cycle to `bca` and `cab`, and add all three.

```
(100a + 10b + c) + (100b + 10c + a) + (100c + 10a + b)
= 111a + 111b + 111c
= 111(a + b + c)
```

Since `111 = 3 × 37`, the sum is **always divisible by 37 — and by 3**.

### `abcabc` is divisible by 7, 11 and 13

`abcabc = abc × 1001`, and

**`1001 = 7 × 11 × 13`**

So dividing by 7, then 11, then 13 returns you to **`abc`** exactly.

## Word problems worth the algebra

**Horses and hens.** 55 heads, 150 legs.
Let there be h horses. `4h + 2(55 − h) = 150` → `2h = 40` → **20 horses, 35 hens**.

> [!TIP]
> **Without algebra:** if all 55 were hens there'd be `110` legs. The extra `150 − 110 = 40` legs come from horses having **2 extra legs each**, so `40 ÷ 2 =` **20 horses**.

**Ages.** A mother is 5 times her daughter's age; in 6 years she'll be 3 times.
`5d + 6 = 3(d + 6)` → `5d + 6 = 3d + 18` → `2d = 12` → **daughter is 6, mother 30**.

**Cows.** Naina has twice Gauri's cows; giving away 3 would even them up.
Let Gauri have g, Naina `2g`. `2g − 3 = g + 3` → **g = 6**, so **Gauri 6, Naina 12**.

**Dosa cart.** Rent ₹5,000/day, ₹10 per dosa to make.
- Selling 100 dosas for ₹2,000 profit: `100p − 1000 − 5000 = 2000` → `p =` **₹80**.
- At ₹50 each: `50n − 10n − 5000 = 2000` → `40n = 7000` → **175 dosas**.

**Karim and the genie.** Money doubles each round; he pays the genie 8 coins each time; after the third doubling he has exactly 8 coins — all of which he owes.

Let him start with x:

```
round 1:  2x − 8
round 2:  2(2x − 8) − 8 = 4x − 24
round 3 (after doubling): 2(4x − 24) = 8x − 48 = 8
                                        8x = 56
                                         x = 7
```

**Karim started with 7 coins.**

**Check:** `7 → 14, pay 8 → 6 → 12, pay 8 → 4 → 8, pay all 8 → 0` ✓

> [!IMPORTANT]
> **Why 7 was doomed.** Doubling then paying c leaves `2x − c`, which beats x only when **`x > c`**. Karim had **7, one short of the 8 fee** — so every round left him with less, and the third wiped him out.
>
> **To gain, Karim needed to start with MORE coins than the fee.** Then `2x − c > x`, and the surplus compounds each round. **For the genie to take everything, it just has to set the fee above Karim's current holding.**

**Three magical ponds.** Flowers double in each pond; he leaves the same number f at each of three shrines, ending with none.

Let him start with x:

```
pond 1 → 2x,   leave f  → 2x − f
pond 2 → 4x − 2f, leave f → 4x − 3f
pond 3 → 8x − 6f, leave ALL of it at shrine 3
```

For the third shrine to get f as well: `8x − 6f = f` → **`8x = 7f`**.

For whole numbers take `f = 8`: he started with **7 flowers** and left **8 at each shrine**.

**Check:** `7 → 14, leave 8 → 6 → 12, leave 8 → 4 → 8, leave 8 → 0` ✓

## A pretty sequence

```
        1        1
       ───  =   ───
        3        3

      1 + 3      4        1
     ───────  = ───  =   ───
      5 + 7      12       3

    1 + 3 + 5     9        1
   ───────────= ─────  =  ───
   7 + 9 + 11    27        3
```

**Every one equals 1/3.** 

**Why:** the numerator of the nth fraction is the sum of the **first n odd numbers = n²**. The denominator is the sum of the **next n odd numbers**, which is `(2n)² − n² = 4n² − n² = 3n²`.

`n² / 3n² =` **1/3**, always.
